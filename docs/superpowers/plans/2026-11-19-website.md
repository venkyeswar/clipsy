# Clipsy Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Clipsy promo/help/download website in `website/`: a static React site whose download section updates itself from GitHub Releases.

**Architecture:** Vite + React + TypeScript single page. Pure, unit-tested logic in `src/lib/` (release parsing, demo state). UI composed from shadcn/ui components styled with Tailwind; Motion for animation. Releases fetched in the browser with a cache and a build-time snapshot fallback.

**Tech Stack:** Vite, React 18, TypeScript, Tailwind CSS v4, shadcn/ui, Motion (`motion/react`), Sonner, Vitest, @fontsource-variable fonts, GitHub Actions + GitHub Pages.

**Spec:** docs/superpowers/specs/2026-11-19-website-design.md

## Global Constraints

- All site code lives under `website/`; do not touch Rust crates.
- UI components come ONLY from shadcn/ui (added with `npx shadcn@latest add <name>`); keycaps and the demo are composed from them with Tailwind. No other UI kits.
- Fonts: Familjen Grotesk (display), Onest (body), JetBrains Mono (commands/keycaps) via `@fontsource-variable/familjen-grotesk`, `@fontsource-variable/onest`, `@fontsource-variable/jetbrains-mono`.
- Palette tokens (shadcn CSS variables, both themes, verify WCAG AA for every text/background pair): Dark: background `#171a21`, surface `#20242d`, text `#e9ebf1`, muted `#9aa1b0`, accent `#f0592b`, secondary `#3fb8c9`. Light: background `#f5f7fb`, surface `#ffffff`, text `#1b1f29`, muted `#5d6577`, accent `#d8431a`, secondary `#0f8aa0`. Adjust a value only if a pair fails AA.
- Theme follows `prefers-color-scheme` by default with a header toggle persisted in `localStorage` (guard with try/catch).
- Copy style: sentence case, plain verbs, no ALL-CAPS eyebrow labels, no single-word color accent in headlines, no numbered cards unless the content is a sequence.
- Motion: one orchestrated moment (hero demo autoplay). Elsewhere only motion that responds to an action. No scroll-triggered fade-ins. Respect `prefers-reduced-motion` (hero shows final state, no autoplay).
- Responsive from 360px wide: no horizontal page scroll, 16px side gutters, 44px minimum touch targets, visible keyboard focus, semantic landmarks.
- Every task ends green on: `cd website && npm run lint && npm test -- --run && npm run build`.
- Commits: author is the user's configured git identity; do NOT add any Co-Authored-By line.
- Repo: `venkyeswar/clipsy`. GitHub Pages base path: `vite.config.ts` uses `base: process.env.VITE_BASE ?? "/"`.

## Review Focus

- Releases API fails, is rate-limited (403), returns `[]`, or returns a release with no `.deb`: the page still renders with the snapshot or a "View on GitHub" fallback and no broken or empty download button.
- Draft and pre-release entries must never be "latest"; versions sort by semver (`0.10.0` > `0.9.2`), not by date or string order.
- Demo "Clear" semantics match the real app: All clears everything unpinned; Text/Images/Files clear only that kind (Text includes html); ★ clears pinned; "Also remove pinned items" defaults unchecked and is hidden on ★.
- `localStorage`/`sessionStorage` throw (private mode): theme and cache degrade silently.
- Copy buttons: clipboard API unavailable or denied shows a fallback ("Press Ctrl+C") rather than a silent failure.
- Both themes legible at 360px; hero demo usable by keyboard (tab order, focus visible, dialog traps focus).

### Task 2: Release data layer

**Files:**
- Create: `website/src/lib/releases.ts`, `website/src/lib/releases.test.ts`, `website/src/hooks/use-releases.ts`, `website/scripts/generate-snapshot.mjs`, `website/src/data/releases.snapshot.json` (initial `[]`)
- Modify: `website/package.json` (`prebuild` runs the snapshot script; failure of the script must not fail the build — it writes the previous/empty snapshot)

**Interfaces:**
- Produces in `releases.ts`:
  ```ts
  export type ReleaseAsset = { name: string; url: string; size: number };
  export type Release = {
    version: string; tag: string; date: string; prerelease: boolean; notesUrl: string;
    deb?: ReleaseAsset; tarball?: ReleaseAsset; checksums?: ReleaseAsset;
  };
  export function compareVersions(a: string, b: string): number;       // semver, numeric segments
  export function parseReleases(raw: unknown): Release[];              // drops drafts, tolerant of junk, sorted newest-first by semver
  export function latestStable(releases: Release[]): Release | undefined; // first non-prerelease
  ```
  Asset patterns: deb `/\.deb$/`; tarball `/^clipsy-.*-linux-x86_64\.tar\.gz$/`; checksums `/^SHA256SUMS$/`. Version = tag without a leading `v`.
- Produces `useReleases(): { releases: Release[]; status: "loading" | "live" | "snapshot" | "empty" }`: fetch `https://api.github.com/repos/${config.repo}/releases`, sessionStorage cache 10 minutes (guarded), on failure/403/non-array use the snapshot; `"empty"` when both are empty.
- Script `generate-snapshot.mjs` fetches the same URL, writes `parseReleases`-compatible raw JSON subset to `releases.snapshot.json`; on any error leaves the existing file.
